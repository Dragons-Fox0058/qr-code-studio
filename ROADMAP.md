# Roadmap

This roadmap is a planning document, not a promise that every item is scheduled. Priorities should be revisited as issues, user feedback, and maintenance capacity change.

## Now — reliability and project foundations

- [ ] Keep documentation and contribution guidance current.
- [ ] Establish a repeatable Android build and test workflow after validating the Gradle environment.
- [ ] Review dependency update alerts and resolve actionable security advisories.
- [ ] Document release steps and versioning expectations.
- [ ] Review permission usage and privacy disclosures against actual runtime behavior.

## Next — quality and maintainability

- [ ] Expand automated tests around critical QR creation and scanning flows.
- [ ] Add static analysis and dependency review where compatible with the project.
- [ ] Improve issue triage with consistent labels and milestones.
- [ ] Track known limitations and accepted technical debt.

## Later — product direction

- [ ] Prioritize feature proposals based on user demand and maintenance cost.
- [ ] Evaluate accessibility and localization improvements.
- [ ] Review performance and compatibility across supported Android versions.

## How priorities are selected

A roadmap item should have a clear user or maintenance benefit, a testable outcome, and an issue or discussion when implementation work begins. Security and correctness issues take precedence over cosmetic improvements.
